## 결정 사항 (0단계, 2026-11-24)

현재 목표는 **테스트 버전**이다. Show 작성 → 닉네임 입장 → 실시간 진행 → 리포트·엑셀 흐름이 끝까지 동작하는 것을 우선하고, 인증·본인 확인 같은 세부 기능은 추후 구현한다.

### 사용자 답변으로 정한 것

| ID | 결정 | 영향 |
| --- | --- | --- |
| D-01 | 피교육자는 개인 LTE로 접속한다고 가정(사내 Wi-Fi 사용 안 함) | 공용 IP 문제는 고려하지 않음. 8장 점검은 LTE만 |
| D-02 | 모든 피교육자는 휴대폰이 있다고 가정 | 여분 태블릿·추가 입장 허용 기능 없음. JN-07(기기당 1명) 유지 |
| D-03 | 기기 교체는 없다고 가정 | JN-06의 '다른 기기로 교체' 흐름 제외: 같은 닉네임으로 다른 기기 입장은 거부. 같은 기기는 재접속 토큰으로 자동 복귀. '재접속 허용' 옵션은 항상 On으로 고정(설정 화면에 비활성 표시) |
| D-04 | 일시정지 기능 제외 | PL-09에서 일시정지 제외, 자동 이동의 일시정지도 제외. 전체화면·조작 버튼 숨김은 유지 |
| D-05 | 옵션 토글은 7개(PRD 6종 + 지각 입장 허용, 기본 On) | 4단계부터 `options` jsonb에 7개 모두 저장 |
| D-06 | 마지막 문제 뒤에는 문제별 랭킹 없이 최종 랭킹으로 | 상태 전환: 마지막 문제의 reveal → final |
| D-07 | **사번 대신 닉네임 자유 입력**(형식 검증 없음) | 입장 시 닉네임 하나만 입력(앞뒤 공백 제거, 1~20자). 회차 안에서 닉네임 중복 불가. `participants.nickname` 추가, `emp_no`·`dept`는 nullable로 남겨 추후 사번 인증에 사용. 리포트·엑셀은 닉네임 기준 |
| D-08 | ~~교육자 가입은 이메일 인증 없이~~ | D-26으로 대체(로그인 자체를 없앰) |
| D-09 | 테스트 버전 우선, 인증 등 세부 기능은 추후 | 아래 "추후 구현으로 미룬 것" 참고 |

| D-26 | **교육자 로그인·인증 없음** — 접속자 누구나 교육자 | A1 로그인 화면, SH-01, 라우트 보호, 로그아웃, `hosts` 테이블, `owner_id`/`host_id` 컬럼, Supabase Auth 사용을 모두 삭제. 모든 Show·회차·리포트를 누구나 함께 보고 고칠 수 있음(SH-06은 자연히 충족). 모든 DB 접근은 서버(service role)로만 하고 RLS는 켜 두되 anon 정책은 두지 않음 |
| D-27 | 진행 키(회차별) | 회차를 만들 때 무작위 진행 키를 발급(DB엔 해시)하고, 상태 전환·강퇴·입장 마감 API는 이 키가 있어야 동작. 발표 화면은 키를 쿠키에 보관. 다른 PC에서 열 때는 리포트의 '발표 화면 다시 열기'로 키를 다시 받음. 목적: 폰에서 회차 id를 알아낸 참가자가 진행을 조작하는 것만 막음 |

**로그인 삭제에 따라 받아들이는 위험(테스트 버전 한정)**: 주소를 아는 누구나 Show를 고치거나 지울 수 있고, 리포트(닉네임·점수)를 볼 수 있으며, 참가자가 마음먹고 교육자 화면(`/shows`)을 열면 정답을 볼 수 있다. 실제 운영 전에 교육자 인증을 다시 넣는다.

### 제안대로 정한 것

| ID | 결정 |
| --- | --- |
| D-10 | 대기실에 '입장 마감/재개' 토글. 마감 중에는 신규 입장 거부(재접속은 허용) |
| D-11 | 조기 마감(PL-05)의 '전원' = 현재 접속 중(Presence)이고 강퇴되지 않은 참가자 |
| D-12 | 점수 공식의 t는 T를 넘지 않게 자름 → 정답 점수 500~1000점(×M). 접수는 T + 0.5초까지 |
| D-13 | 순위의 총 응답시간 = 응답한 문항의 `elapsed_ms` 합 + 미응답 문항은 제한시간으로 계산 |
| D-14 | 보기가 2~3개면 있는 블록만 표시(2개면 1×2) |
| D-15 | 엑셀 문제 업로드: 문제가 120자를 넘으면 장문형으로 자동 지정, '번호' 열은 참고용이고 순서는 행 순서 |
| D-16 | 휴지통 30일 경과 항목은 목록에서 숨김만(실제 삭제는 추후). Show를 완전삭제해도 회차·리포트는 유지(`sessions.show_id`는 `on delete set null`, 리포트는 snapshot 기준). 회차 삭제(RP-06)는 회차명 입력 확인 후 실제 삭제 |
| D-17 | 마지막 활동 후 12시간 지난 미종료 회차는 자동 종료 처리(PIN 조회·회차 생성 시점에 정리) |
| D-18 | 효과음은 음원 파일 없이 Web Audio로 합성 |
| D-19 | 실시간 방송은 "다시 확인하라는 신호"로만 쓴다. 상태·정답·순위는 항상 API로 받는다(공개 채널은 누구나 보낼 수 있으므로) |
| D-20 | 응답 수 n/N은 발표 화면이 0.5초마다 API로 조회. Presence는 접속 여부 판단에만 사용 |
| D-21 | 테스트는 Supabase·Vercel 무료 플랜으로. 실제 운영 전에 유료 플랜 검토 |
| D-22 | SheetJS는 npm의 구버전 대신 공식 CDN(cdn.sheetjs.com) tgz로 설치. 막히면 보고 |
| D-23 | Next.js·Tailwind는 설치되는 버전의 공식 방식을 따름(`middleware.ts`/`proxy.ts`, `@theme` 등) |
| D-24 | 문제 이미지 버킷은 공개, 파일명은 추측할 수 없는 UUID |
| D-25 | 명단 없는 회차에서도 부서는 받지 않음(닉네임만) |
